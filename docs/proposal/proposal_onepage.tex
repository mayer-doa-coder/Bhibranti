\section{What will be done}

Large language models answer Bengali examination questions fluently and are
sometimes confidently wrong, which a student cannot detect. We will build a
detector that reads a question, an optional supporting passage, and a candidate
answer, and decides whether that answer is correct or hallucinated. It judges
answers rather than producing them.

Two things will be delivered: a Bengali question-answering corpus in which each
question carries one correct and one hallucinated answer, annotated by native
speakers; and a benchmark of a model ladder over that corpus, from simple
word-counting methods up to pretrained transformer encoders.

% ---------------------------------------------------------------- how
\section{How it will be done}

\textbf{Corpus.} Passages come from Bengali Wikipedia and questions from
BCS-style question banks, with the licence of each recorded before ingestion.
Each question is paired with a correct answer and a hallucinated one written
from the same source text under constraints on length and register, so the two
are not separable by surface features. The corpus covers two conditions:
has-context, where a passage is supplied and the answer must be supported by it,
and no-context, where none is. Targets are at least 4{,}000 pairs, a 60/40
split between the two conditions, and an exact 50/50 balance of correct and
hallucinated answers. Splits of roughly 70/15/15 are generated by script and
grouped by pair, so both answers to a question stay together and a model cannot
score by recognising the question. Every stage runs at a fixed seed, so the
corpus rebuilds identically.

\textbf{Annotation.} Two native Bengali speakers label independently, following
guidelines written before annotation begins. They record the binary label, the
error type when an answer is wrong, and a difficulty judgement. A blind sample
of 100 items is labelled first and scored with Cohen's kappa; full annotation
starts only once agreement reaches 0.60. If it does not, the guidelines are
revised and the same items relabelled. The test split is labelled by both
annotators with disagreements adjudicated.

\textbf{Models.} A ladder is built in ascending order of capacity, so each rung
is an interpretable floor for the next: n-gram features with logistic regression
and SVM; skip-gram and word2vec embeddings; BiRNN and BiLSTM with attention; and
pretrained encoders including BanglaBERT, MuRIL, XLM-R, mBERT and IndicBERT v2,
followed by further pretraining and a soft-voting ensemble. Three input formats
are compared, since format often matters more than architecture. Retrieval is
prohibited at inference: the model sees only the question, the stored passage
where one exists, and the candidate answer.

\textbf{Evaluation.} The primary metric is macro-F1, which weights both classes
equally. Every result is reported separately for has-context and no-context, for
easy and hard items, and by subject, because a single averaged number hides the
differences that matter. Each configuration runs with three seeds and reports
mean and standard deviation, with McNemar's test and bootstrap confidence
intervals before claiming that one model beats another.

\textbf{Validity.} Before any score is trusted, the corpus is audited for
shortcuts. A classifier trained only on surface features of the answer, with no
content words, must fail to predict the label; this is a blocking gate. A string
matcher that calls an answer correct whenever it appears in the passage is also
measured, and every grounded score is reported beside it, since such a rule can
score highly without learning anything. Pairs it cannot solve are marked hard,
and the hard subset is the headline result.
